# 青柠记账 Lime Ledger — 官网

虚构的 iPhone / Mac 记账应用「青柠记账」的静态官网。纯 HTML / CSS / JS，无构建步骤、无运行时依赖、不请求任何外部 CDN 或网络字体，把整个目录放到任意静态托管即可上线，也可以直接用 `file://` 打开浏览。

```bash
python3 -m http.server 9101   # 在本目录执行，然后访问 http://localhost:9101/
```

### 维护说明

不使用构建工具，因此每个页面都包含完整的 `<head>` 公共部分、页眉和页脚，分别位于 `<!-- head:start -->`、`<!-- header:start -->`、`<!-- footer:start -->` 注释标记之间。修改导航或页脚时，请在全部 12 个页面中同步修改：根目录页面使用 `assets/...` 相对路径，`blog/` 下使用 `../assets/...`，`404.html` 使用 `/assets/...` 绝对路径。当前页在导航中用 `aria-current="page"` 标记，博客文章页用 `aria-current="true"` 标记所属的“博客”栏目。

## 主要设计决策

按照 Apple-Style 技能的工作流程，先分别确定以下四点，再选组件：

- **目标平台**：跨平台网页（访客用 iPhone、iPad、Mac、Windows 和 Android 浏览器访问）。
- **应用类型**：内容型营销网站。因此不使用 `.as-window`、侧边栏、检查器或 `data-platform="macos"`；宽屏桌面不需要伪装成原生窗口。
- **输入方式**：触控、指针和键盘都要支持。触控目标的尺寸按输入方式（`any-pointer: coarse`）判断，不按屏幕宽度判断。
- **容器宽度**：320–1920 px 连续适配。

**内容层与控制层。** Liquid Glass 只用在浮动的导航控制层：页眉导航组（regular 玻璃组）、唯一着色的主操作“免费下载”（prominent）、菜单按钮，以及紧凑菜单（大玻璃）。正文、卡片、表格、表单全部使用实色或标准材质，没有玻璃叠玻璃，也没有混用 regular 与 clear。页眉本身不铺背景，而是用软性滚动边缘效果（HIG *Scroll views*）。因为营销页会把大字和插图滚到品牌名下面，这个效果比库的默认值调得稍强。页眉经过始终为深色的区块时，`site.js` 会让滚动边缘改为压暗，而不是泛白（HIG：“when content darkens the glass, it switches to a subtle dim”）。

**颜色。** 使用库里的语义色（label、secondaryLabel、separator、fill……），所有自定义颜色都用 `light-dark()` 写成浅色和深色两组值，并为“增强对比度”另配一组。品牌青柠色 `#9bd83a` 只用于插图和图标：它与白色的对比度只有 1.7:1，不能用作文字颜色。文字和白字按钮使用更深的叶绿色，以下数值均为实测：

| 用途 | 浅色 | 深色 |
|---|---|---|
| 白字填充按钮 `--as-action-bg` | `#2b7510`，白字 5.75:1 | `#2f7d14`，白字 5.17:1 |
| 强调文字 / 链接 `--as-accent` | 5.75:1（白底），5.28:1（`#f5f5f7` 底） | `#a6e36a`，13.8:1（黑底） |
| 着色按钮上的文字 `--as-accent-on-tint` | `#22600c`，6.16:1 | `#a6e36a` |

**字体。** 字体栈为系统字体（Apple 设备上即 SF + 苹方）加各平台中文字体，不打包也不自托管 SF。库组件里为拉丁字母设计的负字距，在中文页面中恢复为 0。中文标题使用 `word-break: keep-all`，只在标点、空格和 `<wbr>` 处换行，避免单字落行；`overflow-wrap: anywhere` 作为兜底。正文行高为 1.6–1.85（中文比拉丁文需要更松的行距），长文的行宽限制在 680 px 以内。

**密度与布局。** 采用库的默认 iOS 密度（17 px 正文、44 px 控件）。`data-density="desktop"` 面向桌面 Web 应用，不适合营销页。下列数值都是本项目的默认值，不是 Apple 规范：左右边距 16 / 24 / 40 px；内容最大宽度 1200 px，≥1600 px 时为 1280 px；正文 680 px；断点 600 / 900 / 960 / 1024 px。区块背景通栏铺满，因此 1920 px 下两侧不会出现留白的“死边”。

**组件语义。**
- 价格周期和外观切换使用 `role="radiogroup"` 分段控件（选择的是一个值，不是切换面板），支持方向键、roving tabindex 和拖动。
- 紧凑导航是“按钮 + 链接列表”的展开式导航（disclosure），不是 `role="menu"`，所以链接保留原生键盘行为。Esc 关闭并把焦点还给按钮，点击外部也会关闭。
- FAQ 使用原生 `<details>`；对比表使用带 `<caption>` 和 `scope` 的 `<table>`，对勾和横线都配有读屏文字“包含 / 不包含”。
- 表单遵循库的约定：始终可见的 `<label>`、`autocomplete` / `inputmode`、失焦和提交时校验、错误提示紧邻字段（`aria-invalid` + `aria-describedby`，文字说明如何修正），提交失败时聚焦第一个错误字段。成功后把焦点移到结果标题。
- toast 只用于“链接已复制”这类无需操作的确认。

**外观。** 默认跟随系统。页脚可选“自动 / 浅色 / 深色”，选择保存在 localStorage 中，并由 `<head>` 里的内联脚本在首次绘制前应用，因此不会闪烁；`theme-color` 也会同步更新。

**插图与版权。** 所有产品插图都是 HTML/CSS 绘制的界面示意，随主题变色，用 `role="img"` 加完整的 `aria-label` 描述内容。设备外框是通用的圆角边框，没有刘海、灵动岛或按键，不复刻 Apple 硬件。图标均为自绘（24 网格、1.8 描边），没有使用 SF Symbols（其许可不允许用于网页）。页脚附有 Apple 商标声明。

**隐私。** 网站本身不使用 Cookie，不加载统计或第三方脚本；隐私政策第 5 节如实描述了这一点。

**降级。** 没有 JavaScript 时，内容完整可读：价格默认显示按年；外观切换、价格周期和 FAQ 搜索这类只能靠 JS 工作的控件会被隐藏；联系页提示改用邮件联系。

**关于紧凑菜单的一个发现**：菜单打开时从 `scale(.4)` 放大，`liquid-glass.js` 会在起始尺寸下生成折射位移图（120×128 而不是 300×320）。由于 transform 不会触发 ResizeObserver，位移图不会重建，结果是菜单区域内背景几乎没有模糊。因此给这个菜单加了 `data-lens="off"`（运行时提供的开关），让它使用 40 px 模糊的大玻璃材质，并把填充调厚到 84%。

## 上线前需要替换的内容

1. **域名**：把 `https://limeledger.example` 替换为正式域名，涉及每页的 `canonical` / `og:url` / `og:image`、`sitemap.xml` 和 `robots.txt`。
2. **App Store 链接**：所有下载按钮都指向占位地址 `https://apps.apple.com/cn/app/lime-ledger/id0000000000`（页眉、页脚和各页按钮），需要全局替换。拿到 App ID 后，可以在各页 `<head>` 中加入 `<meta name="apple-itunes-app" content="app-id=…">`。
3. **邮箱**：`hello@` / `press@` / `privacy@limeledger.example` 都是占位地址。
4. **表单后端**：在 `assets/js/site.js` 中把模拟发送的 `setTimeout` 换成向表单服务（如 Formspree、Netlify Forms 或自建接口）发起的 `fetch`，校验逻辑可以保留；失败时请在表单内显示错误。
5. **404**：大多数托管平台（Netlify、Cloudflare Pages、GitHub Pages、Vercel）会自动使用根目录的 `404.html`；Nginx 需要配置 `error_page 404 /404.html;`。`404.html` 使用根路径 `/assets/...`，如果部署在子路径下，需要改为对应的前缀。
6. **ICP 备案**：如果托管在中国大陆，必须在页脚加入真实的 ICP 备案号。这里没有编造。
7. **法律文本**：隐私政策是根据虚构产品撰写的示例，正式使用前请由法务审阅。
8. **缓存**：资源文件名没有加哈希。如果要设置长期缓存，请同时为资源加版本号。
