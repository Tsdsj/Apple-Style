# 青柠记账 Lime Ledger · 官网

虚构的 iPhone / Mac 记账应用「青柠记账」的官方网站。纯静态 HTML + CSS + 原生 JS：没有构建步骤，没有外部 CDN、网络字体或第三方脚本，把整个目录上传到任意静态托管就能用。

本地预览：

```bash
python3 -m http.server 9103          # 或者 node tools/serve.mjs（会模拟 404.html 兜底）
# 打开 http://localhost:9103/
```

## 2. 主要设计决策

**克制的 Apple 风格。** 大量留白、居中的大标题、浅灰与白交替的分区、一个强调色、胶囊按钮和“了解更多 ›”式文字链接、毛玻璃吸顶导航。没有装饰性动画；唯一的动效是菜单展开、FAQ 加号旋转和卡片轻微上浮，并全部遵守 `prefers-reduced-motion`。

**不用图片画产品。** 所有 iPhone / Mac 样机、预算圆环、柱状图、规则列表都是 HTML + CSS + 内联 SVG。好处是：随浅色/深色自动切换成对应的 App 界面、任何分辨率都清晰、总体积小（整站约 650 KB，其中 OG 分享图占 230 KB）。样机内部字号用容器查询单位 `cqw`，按机身宽度等比缩放；每个样机都是 `role="img"` 并有完整的文字描述。示意图里的数字前后一致（十月支出 ¥3,268.40 = 各分类之和；预算 ¥5,000 剩余 ¥1,731.60；“还有 12 天”对应 10 月 19 日）。

**颜色与深色模式。** 所有颜色都是 `:root` 上的 token。深色模式默认跟随系统（`prefers-color-scheme`），页脚另有“自动 / 浅色 / 深色”切换，选择保存在 `localStorage`（读写都有 try/catch，隐私模式下也不报错），并在 `<head>` 内联一行脚本提前应用，避免闪烁；`theme-color` 也会同步更新。强调色是青柠绿：浅色模式用深一些的 `#367a0a`（白底对比度 5.3:1，浅灰底 4.9:1），深色模式用亮青柠 `#a3e05a` 配深色文字。

**中文排版。** 只用系统字体栈（Apple 设备上是 SF Pro + 苹方，Windows 是微软雅黑，Linux 是思源/Noto），不加载任何网络字体。正文 17px、行高 1.65，文章 18px、行高 1.85；中文不使用负字距。大标题按短语包在 `inline-block` 里（如“记账，｜本该这么轻。”），保证在 390px 上也不会出现孤字；居中引言使用 `word-break: keep-all` + `text-wrap: balance`，只在标点处换行。中英文、数字之间留空格。

**响应式。** 断点 734px / 834px（导航折叠）/ 1068px。内容最大宽度 1180px，两侧留白 `clamp(20px, 5vw, 48px)`；文章正文 700px。在 390px 到 1920px 的每个宽度都没有横向滚动（见下方检查）。

**无障碍。** “跳到主要内容”链接、语义化地标、每页唯一 `h1`、当前页 `aria-current`、清晰的焦点环；移动菜单有 `aria-expanded`、Esc 关闭并归还焦点、展开时 Tab 焦点限制在页头内、锁定背景滚动；对比表的勾/叉带隐藏文字“包含 / 不包含”；表单每个字段都有 label、错误通过 `aria-describedby` 关联、提交失败时焦点移到第一个错误、状态区 `role="status"` 播报；成功面板获得焦点。

**渐进增强。** 关掉 JS 也能用：导航变成可横向滚动的链接行，价格显示年付并注明月付价格，FAQ 全部可展开（只是没有搜索），表单会被隐藏（避免以 GET 方式把留言拼进网址），改为显示 `<noscript>` 里的邮箱地址。外观切换、价格切换和搜索框在无 JS 时隐藏，不会出现点了没反应的控件。

**路径策略。** 除 404 外全部使用相对路径，因此站点可以部署在域名根目录或任意子目录，甚至直接双击打开。404 页会在任意深度的路径下被返回，所以它使用以 `/` 开头的绝对路径（前提是部署在域名根目录）。

**网站自身也遵守隐私承诺。** 不用 Cookie、不接统计、不请求任何第三方域名——与隐私政策第 8 节的表述一致。检查脚本会拦截并报告任何对外请求。

## 4. 做过的检查

所有检查都可以重复运行（需要 Node 22；浏览器检查使用环境中已安装的 Playwright + Chromium）：

```bash
node tools/check-site.mjs               # 静态检查，约 1 秒
node tools/browser-check.mjs [--shots]  # 浏览器检查，约 2 分钟；--shots 会把截图写到 tools/.output/shots/
```

**静态检查（`check-site.mjs`）—— 12 个页面全部通过**
- 每页都有 doctype、`lang="zh-CN"`、charset、viewport、标题、描述、`<main>`、跳转链接；`h1` 恰好一个；标题层级不跳级。
- 标签全部正确配对；无重复 id；所有 `img` 有 `alt`；所有 `button` 有 `type`。
- `label[for]`、`aria-labelledby`、`aria-describedby`、`aria-controls` 引用的 id 都存在。
- 所有内部链接、资源文件和 `#锚点` 都能解析到真实文件与元素（包括页脚里的 `faq.html#cancel-subscription`、`privacy.html#subscription` 等）；没有 `href="#"` 空链接。
- HTML、CSS、JS 里没有任何外部资源引用、`@import` 或 `@font-face`；`sitemap.xml` 里的每个地址都对应真实页面。
- 仅有的 3 个外部 `<a>` 链接已人工确认：Apple 退款页（真实地址）和两个 App Store 占位链接。
- `sitemap.xml`、`feed.xml` 可被 XML 解析，`site.webmanifest` 是合法 JSON。

**浏览器检查（`browser-check.mjs`）—— 全部通过**
- **布局：** 12 个页面 × 5 种宽度（390 / 768 / 1024 / 1440 / 1920）× 浅色 / 深色 = 120 种组合，均无横向溢出、无控制台错误、无 4xx/5xx、无对外请求，图片全部加载成功。
- **对比度：** 遍历所有可见文字（装饰性样机除外），按实际前景色、叠加后的背景色和不透明度计算，在 390 和 1440 宽度下浅色、深色各约 2,400 处文字（12 个页面合计）全部达到 WCAG AA（正文 4.5:1，大字 3:1）。这个检查实际发现过两处问题并已修复：分段控件未选中项（4.15:1）和深色模式下“省 32%”（4.37:1）。
- **交互：** 移动端菜单（展开、焦点、Tab 限制、Esc 关闭、点链接跳转）；首个 Tab 落在可见的“跳到主要内容”；外观切换生效、跨页面保持、可切回自动；价格按月 / 按年切换的金额、单位、说明和按钮文字；FAQ 搜索、无结果空状态、清除搜索、锚点自动展开；联系表单的 `?topic=` 预选、空表单 5 项报错并聚焦第一项、邮箱格式提示、提交中禁用按钮、成功面板显示邮箱并获得焦点、“再写一条”重置；文章页复制链接；深层不存在路径返回 404 状态码且样式与图片正常；禁用 JS 时导航可用、无溢出，联系表单隐藏并显示邮箱替代方案。

**人工视觉检查**
- 逐页查看了 390 / 1440 / 1920 宽度、浅色与深色的整页截图，以及表单错误态、成功态、移动端展开菜单。由此修正过：样机容器查询单位的作用对象、机身边框比例、引言在词中间换行、表单“（选填）”误用胶囊样式、同意条款文字误加粗、隐私页日期换行、免费方案卡底部留白等问题。

**已知局限**
- 检查环境只有 Chromium，未在真机 Safari / iOS 上测试；用到的较新特性（`cqw`、`text-wrap: balance`、`:has()`）在不支持的浏览器上会安全降级（固定字号、普通换行、少一个焦点细节）。
- 截图环境的中文字体是文泉驿，与苹方在字重和字宽上有差异；在 Apple 设备上标题会更紧凑。
- 手机宽度下，Mac 样机里的文字很小，它只作为示意图出现，关键信息都在旁边的正文里。
