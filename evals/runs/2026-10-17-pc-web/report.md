# 再评估：用 Apple-Style 技能做一个真实的 PC 端网页

日期：2026-10-17　·　库版本：`main` @ `f921bbc`（已含审计 §2.1–2.10 的修复）　·　环境：Chromium 141 headless，Linux 容器

> 结论：用这套技能能在较短时间内做出**观感可信、键盘与深浅色都过关**的桌面 Web 应用骨架（侧栏 + 列表 + 详情 + 工具栏 + 对话框）。但它还不是“拿来即用”：一个普通的工单后台页用到了库的 33 个类和 20 个语义变量，此外仍需页面自写 **68 行补能力的 CSS、12 行绕过库缺陷的 CSS**，以及列表键盘交互、对话框接线等脚本；并且这次实测又发现了 **3 个库级缺陷**（分栏变量只在 `.as-window` 上定义、次要文字色与 tinted 按钮在浅色下对比度不足）。

## 1. 方法

1. **只按技能走**：读 `SKILL.md` → `rules-and-evidence.md` → `web-implementation.md` / `materials-and-liquid-glass.md`，再看 `web/demo*.html` 的标记写法，然后实现。
2. **四项独立判断**（`rules-and-evidence.md`）：平台 = 跨平台桌面浏览器；产品 = Web 应用（工单后台）；输入 = 指针 + 键盘；容器 = 1024–1920px。结论：不模拟原生窗口和菜单栏，不设 `data-platform="macos"`；侧栏和详情栏由“列表 → 详情”的信息结构决定。
3. **产物**：[`index.html`](index.html)——侧栏导航、工具栏（搜索 / 状态筛选 / 新建）、可键盘操作的工单列表、详情栏（属性、开关、操作、动态）、新建工单对话框（文本框、文本区、分段、可定制 select、开关、校验）、Toast、加载与空状态，数据为模拟。页面 CSS 中库没有的部分都标了 `[gap]`、`[defect]` 或 `[page]`。
4. **检查**：按 Review 技能的证据格式，用 [`check.spec.js`](check.spec.js) 自动化（axe-core 4.10.2 扫描、多宽度布局、键盘全流程、强制颜色、减少动态效果），截图在 [`evidence/`](evidence/)。
5. **偏差声明**：评估者就是做审计和修复的同一个 Agent，比“第一次接触这套技能的 Agent”更熟悉内部结构，因此本结果偏乐观；冷启动的易用性仍需跑 `evals/` 的启用/关闭对比来证明。

## 3. 技能直接给到的（做得好的部分）

- **规则层判断准确**：四项独立判断让我没有把网页做成假 Mac 窗口；`web-implementation.md` 里关于对话框（`<dialog>`、焦点、Esc、焦点回归）和表单（label、`aria-describedby`、`aria-invalid`、失焦/提交时校验）的要求具体、可照做。
- **语义色与深色模式**：一行深色专用样式都不用写。
- **分栏**：`.as-split` + `.as-split-divider` 直接得到可拖拽、可键盘调节、ARIA 数值正确的分栏，窗口变窄时自动归还空间。
- **控件**：分段控件（radiogroup、方向键、拖拽）、开关（点击/键盘/拖拽、取消不提交）、聚焦环、强制颜色和减少动态效果下的表现，都开箱即用。
- **桌面工具栏**：`.as-toolbar-window` 加上硬边滚动效果，就能得到无边框按钮的桌面工具栏。
- **接入**：`import { init } from 'liquid-glass.mjs'` 一行即可，动态渲染的列表和详情由运行时自动升级，无需手动调用 `init`。

## 4. 本次新发现的库级缺陷

| 编号 | 优先级 | 问题 | 复现 / 证据 | 建议修复 |
|---|---|---|---|---|
| D1 | P1 | `.as-split` 各栏读取的 `--as-sidebar-w`、`--as-inspector-w`、`--as-content-min`、`--as-row-min` **只在 `.as-window` 上定义**；Web 应用不用 `.as-window`（它默认带菜单栏）时，栏宽塌成内容宽度、行高塌成 0 | 第一版截图里侧栏行和属性行挤在一起，详情栏异常宽 | 把这些变量定义到 `.as-split`（或 `:root`）上，`.as-window` 只负责覆盖；并让 `.as-window` 不强制要求菜单栏行 |
| D2 | P1（无障碍） | `--as-label-secondary` 在浅色下沿用 Apple 原值，白底 **3.44:1**、浅灰底 **3.30:1**，低于 WCAG 1.4.3；它被用于分区标题、属性标签、计数等有意义的小字 | axe 浅色第一轮 68 处对比度失败 | 默认外观改用达到 AA 的值（例如浅色 `rgb(60 60 67 / .78)`：白底 5.63:1、浅灰底 5.26:1），在样式测试中加入次要文字对比度检查 |
| D3 | P2（无障碍） | `.as-button-tinted`（强调色文字配 15% 强调色底）白底 **4.46:1**、浅灰底 **4.04:1** | axe 浅色剩余的那 1 处 | 加深文字色或提高底色比例，纳入对比度测试 |
| D4 | P3 | 运行时生成的分栏拖拽条（`role="separator"`）不在任何地标区域内（axe `region`，最佳实践级） | 浅色、深色各 2 处 | 文档建议把 `.as-split` 放进 `main`，或者让拖拽条归属到相邻地标 |
| D5 | 设计 | 大玻璃（约 70% 填充）用作表单对话框时，背后列表文字透出来，影响可读性；库没有不透明的模态材质可选 | `dialog-light.png` 修正前后对比 | 提供 `.as-glass-modal` 或厚材质变体（约 94% 填充） |
| D6 | P3 | 窄于 1024px 时三栏直接堆叠，侧栏占满首屏；Web 应用更常见的是可折叠侧栏 | `layout-720.png` | 提供侧栏折叠/抽屉模式的示例 |

## 5. 页面必须自己补的能力（库缺口）

| 缺口 | 页面代码 | 说明 |
|---|---|---|
| 桌面 Web 密度档 | 4 行 CSS | 库只有 iOS 档（17px / 44px）和 macOS 档（13px / 22px）；分栏内部已是 13px，按钮、分段、搜索仍是 iOS 尺寸，同一页面里密度不一致 |
| CJK 字体与字距 | 3 行 CSS | 字体栈没有中文字体，字阶用的是拉丁文字距 |
| 可选择的列表（listbox） | 12 行 CSS + 约 10 行 JS | `.as-list` 是 iOS 分组列表，`.as-list-column` 没有行样式 |
| 表单控件 | 15 行 CSS | 文本框、文本区、pop-up 按钮（select）、标签、提示、错误；库只有玻璃搜索框 |
| 模态对话框 | 8 行 CSS + 约 8 行 JS | `.as-sheet` 是需要自写脚本的 iPhone 半屏面板；桌面端用 `<dialog>.showModal()` |
| 状态标签 | 7 行 CSS | 库只有红色计数徽标 |
| 空状态与加载态 | 7 行 CSS | 速查表要求有，但库不提供 |
| Toast | 3 行 CSS + 约 4 行 JS | z-index 表里有 toast 层级，但没有组件 |
| 自定义组件的强制颜色适配 | 4 行 CSS | 库只处理自己的控件 |

合计：页面 CSS **89 行声明**（`[gap]` 68、`[defect]` 12、`[page]` 9），页面 JS 78 行（其中约 22 行补的是库缺的交互）。页面用到了库的 33 个类和 20 个语义变量。

**做“真实 PC 端网页”的能力判断**

- **做内部工具或后台原型**：可以。照着技能能较快得到一个观感统一、键盘可用、深浅色都正确的界面，主要工作量集中在第 5 节那些缺口上。
- **做面向用户的正式产品**：需要先修 D1–D3，并补上桌面 Web 密度档和表单/选择/列表/对话框这类组件，再在 Safari、Firefox 和读屏软件上实测。
- **做营销 / 内容网站**：这次没有测。组件以 App 结构为主，审计第 4 节指出的“内容网站模式缺失”依然成立。
