# 青柠记账 Lime Ledger 官网

为虚构的 iPhone / Mac 记账应用「青柠记账」制作的静态官网。纯 HTML、CSS 与少量原生 JavaScript，没有构建步骤，没有外部 CDN，也没有网络字体。把整个目录上传到任意静态托管（Nginx、GitHub Pages、Netlify、Cloudflare Pages、对象存储等）即可使用。

站点假定部署在域名根目录下，所有链接与资源路径都以 `/` 开头。

## 主要设计决策

**克制的视觉语言。** 页面以白色和浅灰（`#f5f5f7`）为底，文字使用接近纯黑的 `#1d1d1f`，几乎不用阴影。只有一种强调色，即深青柠绿 `#3f7d0c`，它和应用图标的渐变一致。大段留白、居中的大标题、圆角卡片与胶囊按钮，构成整体的 Apple 式节奏。

**设计令牌。** 颜色全部定义为 `:root` 上的 CSS 变量。深色模式通过三处规则覆盖同一组变量：`@media (prefers-color-scheme: dark)` 配合 `:root:not([data-theme="light"])`，以及 `:root[data-theme="dark"]`。页面右下角的「外观」按钮可在「跟随系统 / 浅色 / 深色」之间切换，选择保存在 `localStorage` 中。所有存储读写都包在 try/catch 里，存储不可用时页面仍可正常显示。

**深色模式的强调色。** 深色背景下，强调色改为更亮的 `#a6dc4a`，按钮文字改为深色，以保证对比度。

**响应式布局。** 内容容器宽度为 `min(100% - 32px, 1080px)`，即手机端两侧各 16px 边距，桌面端内容最宽 1080px 并居中，因此 1920px 大屏不会拉伸成一条长线。断点只有两个：760px（卡片从单列变为双列或三列，导航切换为菜单）和 900px（联系页分为两栏）。手机端不会出现页面级横向滚动。价格对比表放在可横向滚动的容器中，只在表格内部滚动。

**渐进增强。** 页面在 `<head>` 中先把 `class` 设为 `no-js`，JS 运行后改为 `js`。只有在 JS 可用时，移动端导航才会折叠为菜单；没有 JS 时，导航链接会直接换行显示，所有内容都可以阅读。

**无外部依赖。** 字体只使用系统字体栈（`-apple-system`、`PingFang SC`、`Hiragino Sans GB`、`Noto Sans CJK SC`、`Microsoft YaHei` 等）。图标是内联 SVG 或 CSS 绘制，手机界面示意也是纯 HTML 加 CSS。页面不加载任何第三方脚本、样式或图片，也没有分析与广告代码。

**表单。** 联系表单在浏览器中完成校验：必填项、邮箱格式、留言不少于 10 个字、隐私政策勾选。错误信息就近显示，`aria-invalid` 与 `aria-describedby` 同步设置，提交失败时焦点移到第一个出错字段。提交成功后显示 `role="status"` 的反馈，并重置表单。按照要求，本站没有真实后端，表单内容不会离开浏览器，页面上也注明了这一点。接入真实服务时，只需在 `site.js` 的提交回调中把数据发送到你的接口。

**可访问性。** 每个页面只有一个 `h1`，标题层级连续；导航有 `aria-label`；有跳到正文的链接；所有表单控件都有可见的 `label`；装饰性的 SVG 与手机示意使用 `aria-hidden`；尊重 `prefers-reduced-motion`；焦点样式使用 `:focus-visible` 的可见轮廓。

**文案。** 全部为简体中文，虚构的产品、团队成员、数据与日期，仅用于演示。

## 部署前需要替换的占位内容

- `https://lime-ledger.example`：出现在 `<link rel="canonical">`、`og:url`、`sitemap.xml`、`robots.txt` 中，改为真实域名。
- `https://apps.apple.com/app/id0000000000`、`.../id0000000001`：iPhone 与 Mac 的 App Store 下载链接，目前为占位 ID（页面中共 4 处，位于首页与价格页的下载按钮上）。
- `support@`、`hello@`、`privacy@lime-ledger.example`：邮箱地址。
- 联系表单：接入留言后端，或者改为第三方表单服务。
- 博客目前只有两篇文章，新增文章时需同步更新 `/blog/index.html` 与 `sitemap.xml`。

## 检查记录

以下检查由 Playwright（Chromium headless shell）在本地 `http://127.0.0.1:9412` 上完成。

- **页面可用性：** 全部 11 个页面（含 404）返回 200；所有站内链接与 `/#download`、`#main` 等锚点目标均存在。
- **视口：** 对 390px、768px、1920px 三种宽度，浅色与深色两种模式，逐页检查：
  - 无页面级横向滚动（`scrollWidth` 不超过 `clientWidth`），无元素超出视口；
  - 所有图片有 `alt`，所有输入框、下拉框、文本域都有关联的 `label`；
  - 每页恰好一个 `h1`，`lang="zh-CN"`，标题非空；
  - 深色模式下 `body` 背景为 `rgb(0, 0, 0)`，浅色模式下为 `rgb(255, 255, 255)`。
- **对比度：** 在浏览器中逐个计算文字节点的前景色与实际背景色的对比度（已考虑祖先元素的 `opacity`）。全站正文最低对比度为浅色模式 4.66:1、深色模式 6.61:1，均满足 WCAG AA 的 4.5:1 要求（大字号 3:1）。
- **网络与控制台：** 没有控制台错误、页面异常、请求失败，也没有任何外部域名请求。
- **交互：**
  - 移动端菜单可打开与关闭，按 Escape 可关闭并回到按钮，点击菜单链接会自动收起；
  - 外观按钮按「跟随系统 → 浅色 → 深色」循环，刷新后保持，清除偏好后恢复跟随系统；
  - 价格页「按年」切换为 ¥98，「按月」恢复 ¥12，`aria-pressed` 同步；
  - 联系表单空提交时显示全部 5 条错误，焦点移到姓名；修正错误后对应提示消失；提交成功后显示反馈并清空表单。
- **视觉：** 手动查看了 390px 与 1920px 下的首页（浅色、深色）、价格页、功能页、联系页、FAQ、文章页、关于页、隐私页、404 页面的整页截图，版式、间距与深色配色均符合预期。

**未完成的检查：** 没有运行 axe-core 自动化无障碍扫描，因为本次任务限定不读取 `/home/user/Apple-Style` 目录下的文件，而 axe-core 位于该目录中。无障碍方面的检查改为上述 DOM 检查与对比度计算。

**需要注意的限制：** 中文字体依赖访问者的操作系统。在没有中文字体的 Linux 环境下，文字会回退到可用的 CJK 字体。本地预览服务器不处理 404 回退，`404.html` 需要在托管平台上配置为错误页面后才会对未知路径生效。
