# 青柠记账 Lime Ledger 官网

iPhone 与 Mac 记账应用「青柠记账」的静态官网。纯 HTML、CSS 和少量 JavaScript，不需要构建工具，不依赖外部 CDN 或网络字体。把整个目录上传到任意静态托管即可（站点根目录就是这个目录）。

## 页面结构

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` (`index.html`) | 首页 | 首屏（分栏，右侧为 HTML 绘制的应用界面）、功能卡片、隐私要点、价格摘要、行动号召 |
| `/features.html` | 功能介绍 | 四组功能：快速记账、账本与预算、报表与复盘、iPhone 与 Mac |
| `/pricing.html` | 价格 | 免费版与订阅版两张方案卡，以及完整功能对比表（可横向滚动，首列固定） |
| `/faq.html` | 常见问题 | 三组，共 12 个问题，使用原生 `<details>` 折叠 |
| `/blog/` | 博客列表 | 三篇文章的列表 |
| `/blog/why-local-first.html` 等 | 文章 | 三篇：为什么留在设备上、月初预算、一句话记账 |
| `/about.html` | 关于我们 | 三条理念卡片、一段故事、合作入口 |
| `/contact.html` | 联系我们 | 联系方式 + 表单（姓名、邮箱、主题、留言），带校验、错误摘要和提交反馈 |
| `/privacy.html` | 隐私政策 | 带目录、最后更新日期的法律页面（示例文字，非法律意见） |
| `/404.html` | 404 | 返回 404 状态，带 `noindex`，根路径资源 |

另有 `robots.txt`、`sitemap.xml`（11 个规范地址）、`icon.svg`、`apple-touch-icon.png` 和 `img/social.png`（1200×630，用于 Open Graph）。

## 文件组织

- `css/apple-core.css`：Apple-Style 核心层（tokens、base、glass、controls、preferences）加上站点头部、导航、页脚和分节样式。所有页面都加载。
- `css/landing.css`：首页、价格、常见问题用到的 hero、价格、FAQ、界面示意和动效样式。
- `css/article.css`：文章正文、法律页与 404 样式。
- `css/listing.css`：博客列表、面包屑和文章链接样式。
- `css/forms.css`：表单样式。
- `css/site.css`：本站的品牌和版式（中文字体、青柠色、页面布局）。最后加载。
- `js/site-nav.js`：窄屏导航折叠，是 Apple-Style 技能中 `web/js/site-nav.js` 的逐字节副本。
- `js/contact.js`：联系表单的校验与反馈脚本（见下文"表单"）。

以上 CSS 是从技能源文件拼接而成，未压缩，便于维护。

## 主要设计决策

- **克制的 Apple 风格。** 大号标题、留白、系统语义色（`light-dark()` 随系统切换浅色与深色）。内容区域是实底卡片，没有玻璃材质；只有导航头部使用 Apple-Style 的标准材质。没有假窗口、标题栏或底部标签栏。
- **品牌色。** 青柠绿 `#3f6b00`（浅色）与 `#bfe86b`（深色）。文字颜色与按钮底色都按背景实测过对比度（白字按钮 6.34:1 / 5.15:1，正文强调色 6.34:1 / 5.68:1）。亮青柠色 `#b6e33a` 只用于装饰（标志、列表圆点），从不承载文字。
- **中文排版。** 字体栈先列 PingFang SC、Hiragino Sans GB、Noto Sans CJK SC、Microsoft YaHei，再回落到系统字体。中文段落行高 1.7，去掉了西文的字距收紧。没有自托管或内嵌任何字体文件。
- **导航。** 全宽头部，六个链接；宽屏完整显示，窄屏（768px 以下）收进"菜单"按钮，按钮与链接按技能的披露模式实现。
- **界面示意不加设备边框。** 首页的"本周概览"是普通 HTML 文字，不是图片，也没有 iPhone 或 Mac 外框，避免绘制 Apple 产品。没有使用 App Store 徽章，因为应用未上架，也没有真实的下载链接。
- **价格。** 免费版：1 个账本、每月 300 笔、最近 90 天报表、不同步。订阅版：年付 ¥98 或月付 ¥12，含 14 天试用，不限账本与记录，周报月报，iCloud 同步，Mac 版，家庭共享（最多 5 人）。两个方案的"了解功能"按钮都指向对比表，因为站点没有购买入口。
- **表单。** 没有后端。提交时在前端校验，错误摘要获得焦点并链接到各字段；校验通过后显示成功消息（`role="status"`）并清空表单。**表单不会发送任何数据。** 接入真实服务时，把 `<form>` 的提交地址指向服务端或表单服务，并改用技能的 `js/site-form.js`（`data-ajax` 模式）。蜜罐字段仍保留，但它不是唯一的防垃圾手段。
- **可访问性。** 跳过链接、唯一的 `h1`、标题层级不跳级、表格有 `caption` 和作用域表头、正文链接保留下划线、焦点环可见、触控目标不小于 44px。
- **SEO 与元数据。** 每页有唯一的 `<title>` 和描述、`lang="zh-Hans"`、规范地址（canonical）、Open Graph 与 Twitter 卡片、颜色方案元标签，首页和文章有 JSON-LD（仅包含页面上可见的信息）。

## 需要上线前替换的占位内容

- 域名：所有 canonical、Open Graph、sitemap 和 robots 中使用的是 `https://limeledger.example`，需替换为正式域名（生成脚本里的 `BASE` 常量，或直接全局替换）。
- 邮箱：`hello@limeledger.example`，出现在联系页和隐私政策中。
- 下载入口：站点没有 App Store 链接。应用上架后，在"免费开始"按钮和价格页加入正式链接，并按 Apple 的营销指南添加徽章与商标署名。
- 隐私政策：是示例文字，不是法律意见。上线前需要法律审核，并与真实的数据处理方式（表单是否收集、是否接入分析工具）核对。
- 页脚的 Apple 商标署名行按英文通用格式书写，上线前对照 Apple 的商标列表复核。

## 本地预览

```sh
python3 -m http.server 9411 --directory .
```
然后访问 http://127.0.0.1:9411/ 。直接用 `file://` 打开时，根路径资源会失效；请通过服务器访问。
