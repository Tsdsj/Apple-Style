Troubleshooting

Start with the doctor command. Most problems show up there with a suggested fix. This guide lists the error codes, where the logs are and what to include in a bug report.

Last updated 15 October 2026

On this page

  2. Logs
  3. Error codes

  5. Conflicts

Start with doctor

tidepool doctor checks the config file, the sign-in, the route to the endpoint, the TLS certificates and every installed plugin. Each check reports pass, warn or fail:

$ tidepool doctor
[pass] config    tidepool.yaml is valid
[pass] auth      signed in to notes-team
[warn] network   HTTPS_PROXY is set; checking through the proxy
[fail] plugins   markdown-lint 1.2.0 is not executable (E503)
1 failure, 1 warning

The command exits with 0 when no check fails and with 1 when one does. Add --verbose to see the details behind each check.

Logs

Tidepool writes one log file per day to ~/.cache/tidepool/logs/ and keeps seven days of them. Use -v to print informational messages to standard error. Set TIDEPOOL_LOG=debug to log every request. Tokens are never written to the log.

Error codes

Each error message starts with a code. Find the code in the table below.

Error codes and fixes
CodeMessageLikely causeFix
E101config file not foundNo tidepool.yaml in the folder or on the search pathRun tidepool init, or pass --config.
E102unknown keyA typo, or a key from a newer versionFix the spelling. Run tidepool config validate.
E201not signed inNo stored token, and TIDEPOOL_TOKEN is emptyRun tidepool login.
E202token rejectedThe token was revoked or has expiredCreate a new token, then run tidepool login again.
E301conflict on a fileThe pool copy changed after your last pullUse --resolve local or --resolve remote, or edit the file and sync again.
E401request timed outA slow or blocked network, or a proxyCheck the connection. Raise timeout in the config file. Proxies set in HTTPS_PROXY are used.
E402certificate not trustedA corporate proxy re-signs HTTPS trafficAdd the proxy certificate authority with TIDEPOOL_CA_BUNDLE.
E501plugin timed outThe plugin is slow or stuckFix the plugin, or raise timeout_ms in its manifest.
E502plugin wrote invalid JSONA print statement or a banner went to standard outputWrite logs to standard error.
E503plugin is not executableThe execute bit is missing, or the manifest names the wrong fileRun chmod +x on the file, and check executable in the manifest.

A sync is slow

Run tidepool sync --dry-run first. It shows how many files would be uploaded. Then:

  • Add large generated folders, such as build output, to ignore.
  • Raise concurrency up to 16 on a fast connection.
  • Lower it to 1 on a slow or metered connection.

Conflicts

A conflict means the same file changed on this computer and in the pool. Tidepool never overwrites either copy without a choice. tidepool status lists the conflicted files. Then pick one of these:

  • tidepool sync --resolve local keeps your copy.
  • tidepool sync --resolve remote takes the pool copy.
  • Edit the file to combine both, then run tidepool sync again.

Note: tidepool pull --force replaces local changes with the pool copy. It cannot be undone, so run tidepool pull --dry-run first.

Report a problem

Open an issue on the issue tracker. Include the output of tidepool doctor --json and the last 50 lines of the log. Doctor hides tokens, but check the output before you post it, and remove any file names you do not want to share.
