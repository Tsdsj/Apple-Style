Configuration

Tidepool reads one YAML file per project. This guide lists each setting, the order in which values are read and how to check the file.

Last updated 2 October 2026

On this page

  1. Where Tidepool looks
  2. Settings
  3. Ignore rules
  4. Environment variables
  5. Check the file
  6. Secrets

Where Tidepool looks

Tidepool uses the first config file it finds, in this order:

  1. The path given with --config.
  2. The path in TIDEPOOL_CONFIG.
  3. tidepool.yaml in the current folder.
  4. ~/.config/tidepool/config.yaml.

Settings

Every setting has a default. Only pool must be set.

Settings in tidepool.yaml
KeyTypeDefaultDescription
poolstringnone, requiredName of the pool to sync with. Create the pool in the web app first.
rootpath.Folder to sync, relative to the config file.
endpointURLhttps://api.tidepool.exampleAPI host. Change it only for a self-hosted pool.
ignorelist of globs".git/", "*.tmp"Paths that are never uploaded. See the ignore rules below.
concurrencyinteger, 1 to 164Files uploaded at the same time.
keep_historybooleantrueCreate a revision on each sync. Set it to false to keep only the latest state.
timeoutduration30sHow long one request may take before it fails with error E401.
pluginslistemptyPlugins to run, with their options. See the plugins guide.

A complete example

pool: notes-team
root: .
endpoint: https://api.tidepool.example
ignore:
  - ".git/"
  - "*.tmp"
  - "drafts/**"
concurrency: 6
keep_history: true
timeout: 45s
plugins:
  - name: markdown-lint
    version: "1.2.0"
    options:
      max_line_length: 100

Ignore rules

Patterns use glob syntax and are relative to root:

  • * matches any characters within one folder.
  • ** matches any number of folders, including none.
  • ? matches one character.
  • A pattern that ends with / matches a folder and everything inside it.

Negated patterns (starting with !) are not supported. Write a narrower pattern instead.

Environment variables

Values are read in this order. The first one that is set wins:

  1. A command-line flag.
  2. An environment variable.
  3. The config file.
  4. The default.

Check the file

Run tidepool config validate after each change. It reports unknown keys and wrong types with the line number.

$ tidepool config validate
tidepool.yaml: 1 problem
  line 6: unknown key "concurency" (did you mean "concurrency"?)
$ echo $?
3

Exit code 3 means a configuration problem. The full list of exit codes is in the API reference.

To read or change one value from the command line, use tidepool config get concurrency and tidepool config set concurrency 8. config set keeps your comments and the order of the keys.

Secrets

tidepool login stores the token in the system keychain on macOS. On Linux it stores the token in ~/.config/tidepool/credentials, a file that only your user can read. In CI, set TIDEPOOL_TOKEN from the CI secret store instead.
