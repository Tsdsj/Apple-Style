Plugins

Plugins extend a sync at fixed points. A plugin is an executable that reads JSON lines on standard input and writes JSON lines on standard output. Use one written by someone else, or write your own in any language.

Last updated 12 October 2026

Hooks

A plugin takes part in a sync through one or more hooks. Declare the hooks in the plugin manifest.

Plugin hooks
HookWhen it runsAllowed responses
filter_fileOnce for each file that passes the ignore rules, before the file is uploaded{"action": "keep"} or {"action": "skip"}
before_syncOnce before a sync starts. The request includes the number of files.{"action": "continue"} or {"action": "abort", "message": "..."}
after_syncOnce after a sync. The request includes the new revision number.{"action": "continue"}

Install a plugin

Install a plugin by name from the registry, or from a folder on disk.

$ tidepool plugin install markdown-lint --version 1.2.0
Installed markdown-lint 1.2.0 to ~/.local/share/tidepool/plugins/markdown-lint

$ tidepool plugin list
NAME           VERSION  HOOKS
markdown-lint  1.2.0    filter_file, before_sync

$ tidepool plugin remove markdown-lint
Removed markdown-lint.

Installing from a folder copies it. While you develop a plugin, run tidepool plugin install ./my-plugin again after each change.

Enable a plugin

Installing a plugin does not run it. List it under plugins in the config file. Plugins run in the order they are listed. Each request carries the options from the config file under the key options.

plugins:
  - name: markdown-lint
    version: "1.2.0"
    options:
      max_line_length: 100

Write a plugin

A plugin folder holds a manifest named tidepool-plugin.json and the executable it names:

{
  "name": "filter-drafts",
  "version": "0.1.0",
  "executable": "./filter-drafts.py",
  "hooks": ["filter_file"],
  "timeout_ms": 5000
}

For each hook, Tidepool writes one JSON request on a line to the plugin's standard input, and reads one JSON response on a line from its standard output. Write log messages to standard error only. Anything else on standard output is treated as an invalid response. A request looks like this:

{"hook":"filter_file","path":"plans/q4.md","size":2048,"options":{"max_line_length":100}}
{"hook":"before_sync","pool":"notes-team","files":12}

Example plugin

This plugin skips every file whose name ends in .draft.md. It keeps all other files and answers the other hooks with continue:

#!/usr/bin/env python3
import json
import sys

for line in sys.stdin:
    request = json.loads(line)
    if request["hook"] == "filter_file":
        skip = request["path"].endswith(".draft.md")
        response = {"action": "skip" if skip else "keep"}
    else:
        response = {"action": "continue"}
    print(json.dumps(response), flush=True)

Save the script next to the manifest, make it executable with chmod +x filter-drafts.py and install the folder with tidepool plugin install ./filter-drafts.

Timeouts and failures

  • A plugin that does not answer within timeout_ms is stopped, and Tidepool reports error E501. The default is 5000 milliseconds.
  • For filter_file, a failing plugin keeps the file and logs a warning. The sync goes on.
  • For before_sync, a failing plugin stops the sync. Set on_error: continue in the manifest to turn the failure into a warning.
  • A response line that is not valid JSON is reported as error E502.

Security

Note: A plugin runs with your user's permissions and can read every file you can read. Install only plugins you trust, and read the source of a new plugin before you enable it.
