Configuration

Everything Tidepool does for a project is described in tidepool.toml, at the project root.

Finding the file

Tidepool looks for tidepool.toml in the current directory first, then in each parent directory, and stops at the first match. To use a different file, pass --config PATH or set TIDEPOOL_CONFIG. The flag wins over the variable.

Top-level keys

KeyTypeRequiredDescription
namestringyesProject name, shown in doctor output and logs.
versionintegeryesSchema version. Currently 1.
descriptionstringnoOne-line summary of the project.
envtable of stringsnoDefault environment variables for every task. See Environment.
pluginstablenoPlugin specifications, keyed by local name. See the plugins guide.
taskstablenoNamed tasks, keyed by task name.

Tasks

Each entry under [tasks] defines a named task. The fields are:

FieldTypeDefaultDescription
runstring or array of stringsrequiredA string runs through sh -c. An array runs the program directly, with no shell.
descriptionstringnoneShown by tidepool run --help.
inputsarray of globsnoneFiles that affect the task. Used to skip work that has not changed.
outputsarray of pathsnoneFiles the task produces.
depends_onarray of task namesnoneTasks to run first. Dependency cycles are rejected.
envtable of stringsnoneExtra variables for this task only.
timeoutduration10mMaximum run time before the task is stopped.

Here is one task with a shell string and one with an argument array:

[tasks.build]
description = "Compile the app"
run = "make build"
inputs = ["src/**/*.c", "Makefile"]
outputs = ["build/app"]
depends_on = ["gen"]
timeout = "5m"

[tasks.gen]
run = ["./scripts/gen-headers.sh", "--verbose"]

Note: Use the array form when an argument contains spaces or characters the shell would interpret. It avoids quoting problems across shells.

Durations are a number followed by a unit: s, m, h or d, for example 30s, 5m or 2h. Mixed units such as 1h30m are not supported.

Environment

[env] sets defaults for every task. A variable that is already set in your shell is not overwritten. A task's own env table always wins for that task, even over your shell:

[env]
LOG_FORMAT = "json"

[tasks.test]
run = "pytest -q"
env = { PYTHONHASHSEED = "0", LOG_FORMAT = "text" }

Local overrides

Put machine-specific settings in tidepool.local.toml, next to tidepool.toml, and add that file to .gitignore. Tidepool merges it over the main file. Tables merge key by key. Arrays and scalar values replace the value from the main file:

# tidepool.local.toml
[tasks.test]
timeout = "30m"

Validating

Run tidepool config validate after editing the file. It reports each problem with a line number:

$ tidepool config validate
tidepool.toml:9:1: error: unknown key "timout" in [tasks.test]
  did you mean "timeout"?
1 error, 0 warnings

Validation exits with code 3 when it finds errors. Add --strict to treat warnings as errors too.

Warning: Everything in tidepool.toml is committed to git. Keep tokens and passwords out of the file. Reference them from environment variables that your shell or a secrets manager sets.

Schema versions

The version key tells Tidepool how to read the file. Version 1 is the only schema that Tidepool 0.5 reads. Files that declare a newer version are rejected with exit code 3, and the error names the release you need.
