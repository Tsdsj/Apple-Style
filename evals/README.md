# 固定 Skill 评测

本目录提供八个固定任务和记录模板：五个设计判断任务，以及三个完整网站任务（`website-full`、`docs-site`、`landing-pricing`，用 Review 技能的 `scripts/check-site/` 检查）。**目前只有一次探索性的启用/未启用对比（见下），样本不足以得出稳定的质量或性能提升结论。**

单次实做评估（不是启用/关闭对比）：[2026-10-17 PC 端网页](runs/2026-10-17-pc-web/report.md)——用技能实际搭建桌面 Web 应用页面，并用 Review 格式记录检查证据。

探索性启用/关闭对比（每组 2 次，单一任务，不足以下稳定结论）：[2026-10-19 完整官网](runs/2026-10-19-website/README.md)——4 个冷启动 agent 做同一个 12 页官网，用同一套脚本检查；结论见 [网站指导能力审计](../docs/audit/2026-10-19-website-guidance-audit.md)。

网站优先改造后的重测（每组 3 次，覆盖 3 个网站任务，另有 1 组 Web 应用回归；同一模型、样本少，只作方向参考）：[2026-10-19 v2](runs/2026-10-19-website-v2/README.md)。

比较方法：

1. 从同一仓库提交创建两份隔离环境，输入相同任务原文、项目文件、工具和权限。保留用户明确的设计阶段约束。
2. 启用组加载本仓库四个 Skill 及必要速查表；关闭组禁用这四个 Skill，不能把 Skill 内容复制进基础提示。记录实际加载文件的 SHA-256。关闭组的宿主通用规则保持相同。
3. 使用同一提供商、实际可用模型 ID/版本、推理设置与随机参数；运行次序随机化。记录工具限制、时长和 token 用量，不能猜测模型名称或缺失数字。
4. 每个条件至少重复 3 次（单次可作探索，不能当稳定提升）。由不知条件的评审者按 `tasks.json` 的具体检查评分；每项保存 evidence、checked/not-checked/not-applicable 和 pass/fail。
5. 仅对实际得到的原型/实现验证。按需要跑键盘、真实 click、拖拽、取消、浅深色对比度和相应容器检查。模型声称“通过”不是验证证据。
6. 同时报告失败、未完成、无法运行和不适用项；不以文字详尽程度代替结果质量。性能或效率比较需要匹配任务与环境，记录分布和样本量。

每次将 `result-template.json` 复制为 `<pair>-<task>-<condition>-<repeat>.json`；输出和截图保存在对应目录。记录 prompt、model/host、commit、哈希、工具、输出、逐项证据、人工评审者和限制。Safari、Firefox、VoiceOver 未实测即填写 not-checked，不能从其他浏览器外推。
