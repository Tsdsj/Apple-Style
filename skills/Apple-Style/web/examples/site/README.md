# Reference site

A small static site for a fictional product (Ferrule, a planning tool). It shows the website patterns in `cheatsheets/website-patterns.md` on real pages, with the CSS bundles and checks from `cheatsheets/website.md`. Copy the parts you need; nothing here needs a build step or a runtime.

Serve this folder as the root of a host. Asset paths are root-relative (`/css/base.css`), so the pages do not work from a subfolder.

Shared header and footer: the same markup on every page (website.md option 3, hand-copied). The test in `tests/browser/reference-site.spec.js` fails if they differ, apart from `aria-current`.

Not used here, and why:

- **Floating header is used on every page (2.1 variant b).** The full-width bar (variant a) is documented but not shown. One variant keeps the header identical on every page.
- **Scroll edge effect (`.as-scroll-edge`) is not used.** The glass header carries its own edge.
- **No CJK sample.** The `zh` rules in the hero and the article are covered by the other browser specs, not here.
- **No explanatory video with captions.** The only video is the decorative loop.
- **No liquid glass runtime.** `liquid-glass.js` is not loaded anywhere. The page is lens-free; the glass is CSS only.

## Forms without a backend

`/api/contact` and `/api/subscribe` are placeholders. A real site sends the form to its own endpoint, or uses a form service (the choice is the owner's). Without an endpoint, a valid submit gets an error from the host and the page shows the failure message, which is the documented behaviour. The tests mock the endpoint.

## Assets

- **Hero and product images** are drawn for the fictional product (HTML rendered to PNG, then encoded). They are stand-ins for real screenshots of an app.
- **Social image** (`img/social.png`, 1200 × 630, 24.7 KB), used by `og:image`.
- **App Store badge** is a neutral dashed placeholder (`img/store-badge-placeholder.svg`), not Apple artwork. Replace it with the official artwork from Apple's marketing tools, and keep the link to your own App Store page. The text "Available on the App Store." sits next to it, as the guidelines require. The product in this example is not on the App Store.
- **Video** (`video/loop.webm`, `video/loop.mp4`, `video/loop-poster.jpg`) is a 3-second loop, muted, `aria-hidden`, with a visible pause control. It starts paused under reduced motion.
- **No Apple fonts, product images or device frames** are used.

To fit the budget, the core layer was made smaller: rules that no website pattern uses (glass groups, transient glass, the dim layer, the Mac-platform sizes, the customizable select picker, the mini and extra-large buttons and the form row) moved into `app.css`. Reduced transparency cannot be emulated in the browser used here; the moved rules were copied unchanged.

## Brand colour

Ferrule teal, set in `css/site.css` with `light-dark()`: `--as-accent` `#00655d` light and `#5ad9c9` dark; `--as-accent-on-tint` `#00524b` light and `#5ad9c9` dark; `--as-action-bg` `#00655d` light and `#00736a` dark. Ratios, computed with the WCAG formula on the composited backgrounds:

| Pair | Light | Dark |
| --- | ---: | ---: |
| accent text on the page background | 6.95 (white), 6.23 (secondary) | 12.20 (black), 9.89 (`#1c1c1e`), 8.10 (`#2c2c2e`) |
| accent-on-tint text on the tinted button | 7.21 (white), 6.52 (secondary) | 9.72 (black), 7.17 (`#1c1c1e`), 5.80 (`#2c2c2e`) |
| white text on the filled button | 6.95 | 5.74 |

Every value is above 4.5:1. The browser test checks the key pairs in both appearances, and the running link in the article.

## Layout checks

- No horizontal overflow at 320, 390, 768, 1280 and 1920 px on any page (tested).
- Screenshots at 390 and 1280 px in light and dark were checked by eye. Fixes made from them: the feature grid has three cards, so the desktop row has no orphan; the header keeps the same height when the script runs (below).
- The sticky header appears mid-page in full-page captures; that is an artefact of the capture, not a layout bug.

## Layout shift and the header

Without JavaScript, the narrow links wrap onto a second row. `site-nav.js` then collapses them behind a Menu button, and the page below used to move up by 24 to 34 px. Lighthouse measured a layout shift of 0.224 on every page from this alone. `patterns/site-header.css` now keeps a 92 px inner height below 48em (114 px below 23.75em), so the header is the same height with and without the script. The measured shift is 0.011 to 0.016 at 320 to 412 px, which is only the brand and button settling inside the header. The pattern is documented in `website-patterns.md`, *Narrow navigation*.

## axe

`axe-core` 4.10.2 (pinned devDependency), tags WCAG 2.0 A and AA, WCAG 2.1 A and AA, WCAG 2.2 AA and best practice, run on every page in light and dark after the reveal has finished: 0 violations. `incomplete` results (for example, text over the translucent glass) are not violations and were not reviewed one by one.

## Known limits

- Below about 375 px, without JavaScript the links wrap to two rows, so the header is 138 px. The reservation covers that case too (see above).
- The floating header's glass is judged by reasoning, not measurement: the fill is 0.70 white (light) or 0.72 dark (dark) over the page, which keeps black or white text above 4.5:1 over the worst backdrop in either mode. Check over a real photograph on a device with a GPU.
- The hero and product images are drawn, not photographs of an app.
