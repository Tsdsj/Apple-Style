# 改造清单：以网站为主场景

日期：2026-10-19　·　基线：`main` @ `0fbdbe6`　·　依据：[网站指导审计](../audit/2026-10-19-website-guidance-audit.md)（W1–W11）和[冷启动对比数据](../../evals/runs/2026-10-19-website/README.md)

## 背景

实测表明，用这套技能做官网时，无障碍和验证比不用技能更好，但页面更重（LCP 慢 0.7–1.3 秒），网站特有的部分（页眉、页脚、主视觉、价格表、文章排版、上线检查）都要 agent 自己写。

这个项目今后的主场景是网站。它是一个 **skill**，不是 UI 组件库。改造按这个前提进行：

- **skill 交付什么**：判断依据（什么场景用什么）、结构约定（HTML 和无障碍要求）、可复制的参考代码、验证脚本。
- **不做什么**：不再扩张 `as-*` 类和运行时 API，不要求项目整包引入参考 CSS/JS。
- **唯一稳定的接口是 tokens**（CSS 变量）。参考代码可以被复制、改名、删减，agent 应该按项目需要取用。

## 决定

| # | 问题 | 决定 | 理由 |
|---|---|---|---|
| D1 | 原生平台（SwiftUI / UIKit / AppKit）还要不要 | **保留，降为次要分支**。HIG 参考库和原生配方不动，网站路径默认不加载它们。 | HIG 参考库是全部规则的来源，删掉会让网站指导也失去依据；原生配方体积小、维护成本低。 |
| D2 | 整包 `apple-style.css` 还要不要 | **保留，改为由拆分文件生成**，另出压缩版。CI 检查生成文件与源文件一致。 | 已有项目、演示页和测试都直接引用 `apple-style.css`，保留文件名可以不破坏它们。 |
| D3 | 没有官方出处的 apple.com 写法收不收 | **收，统一标为“观察到的惯例”**，写明观察日期，不写成规定。不复制 Apple 的商标、图片、文案或产品名。 | HIG 不覆盖营销网站，完全不收会让 agent 继续各自发挥；标清等级可以避免把惯例当成规范。 |
| D4 | 网站模式以什么形式提供 | **一份模式文档加每个模式一个参考 CSS 文件**，再加一个参考站把所有模式串起来。参考代码沿用 `as-` 前缀，便于和基础层组合、便于测试，但文档写明可以改名。 | 符合“skill 不是组件库”：agent 读的是结构和约定，复制的是小段代码。 |
| D5 | 网站要不要加载 `liquid-glass.js` | **默认不加载**。玻璃靠纯 CSS 显示；需要折射时 `defer` 加载运行时，只挂到页眉或菜单上。窄屏菜单另给一个不依赖运行时的小脚本（≤ 2 KB）。 | 实测里库 JS 有 41 KB 未使用；网站上的交互只有展开菜单。 |
| D6 | 运行时内部要不要拆模块（如单独的 lens） | **先不拆**。阶段 1 完成后按重测结果决定。 | 网站默认不加载运行时后，拆分收益要重新测；拆运行时风险较高。 |
| D7 | 现有 Web 应用组件怎么办 | **保留，移到“Web 应用”分支**，网站路径默认不读。表单输入框、按钮等网站也会用的部分留在公共层。 | 本轮刚补的组件经过测试，网站的联系表单也要用到输入框。 |

```text
skills/Apple-Style/

  cheatsheets/
    rules-and-evidence.md        增加页面类型判断
    website.md                   新增：网站工程（元数据、性能预算、字体、部署、多页维护、框架接入）
    website-patterns.md          新增：网站模式（结构、无障碍要求、响应式、来源等级、验证项）
    web-implementation.md        精简为公共部分（语义、主题、媒体、性能、验证）
    web-app.md                   新增：从 web-implementation 拆出的应用部分（表单、列表、对话框、窗口、密度、运行时生命周期）
    components-quickref.md       分成“网站”和“Web 应用”两节
    ……其余速查表保留，补网页字号和中文排版
  web/
    css/tokens.css               颜色、字号、间距、圆角、动效变量
    css/base.css                 排版、正文链接、焦点、偏好设置、强制颜色
    css/glass.css                材质
    css/controls.css             按钮、开关、分段、滑块、输入框、标签
    css/app.css                  标签栏、侧栏、工具栏、sheet、菜单、列表框、对话框、toast、状态
    css/window.css               Mac 窗口、分栏、检查器、菜单栏
    css/density.css              桌面密度（data-density="desktop"）
    css/preferences.css          偏好设置与强制颜色（含各组件的覆盖，必须最后合并）
    patterns/*.css               每个网站模式一个文件
    js/site-nav.js               窄屏展开菜单，不依赖运行时
    liquid-glass.js / .mjs       应用运行时与折射（保持现有 API）
    apple-style.css              生成：全部 css/ 合并（兼容旧用法）
    apple-style.min.css          生成：压缩版
    examples/site/               参考站：首页、文章页、404
    demo.html / demo-desktop.html  保留，作为 Web 应用演示
  scripts/
    build-css.py                 合并、压缩、检查未定义的 token
    check-site/                  网站检查脚本（Playwright 可选）
```

阶段 1 已按原文件的分节完成拆分（合并顺序 tokens、base、glass、controls、window、app、density、preferences，即原分节顺序）。后续调整的规则是：任何网站模式或参考站用到的样式进入公共层（tokens、base、glass、controls），其余进入 `app.css` 或 `window.css`。

## 风险

- **拆分破坏现有用法**：用 D2 的生成文件兜底，并以“合并结果与拆分前等价”作为阶段 1 的完成标准。
- **模式变成新的组件库**：模式文档以结构和约定为主，参考 CSS 每个文件保持小而独立；新增运行时 API 需要单独说明理由。
- **惯例被当成规范**：每个模式必须标来源等级，Review 检查 agent 是否把惯例写成了要求。
- **评测样本仍然偏少**：4.2 每组至少 3 次，并覆盖 3 种网站任务；结论仍只作方向参考。
